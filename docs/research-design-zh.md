# Multiverse Context：设计说明

日期：2026-11-02  
版本：Context core v0.3.1；Multiverse 原生集成基于上游 v0.1.37

## 目标

本项目为 Multiverse 中的 Agent 提供可共享、可追溯、按需读取的研究上下文。目标场景是跨多轮实验和 Agent 交接的长程研究任务：后续 Agent 能发现已有工作，按需核对来源，并继续推进，而不必依赖前一个 Agent 的私人对话历史。

实现由两部分组成：独立的 Python Context core 负责摘要对象、来源版本、读取和发布；Multiverse 分支把这些能力作为监督器管理的 MCP 工具提供给原生 OpenCode Agent。Context core 本身不创建 Agent，也不调用模型。

## 上下文对象

| 对象 | 摘要记录什么 | 原始依据 |
|---|---|---|
| 仓库 | 项目结构、模块职责、通用规则、重要入口 | Git 文件与仓库规则 |
| Issue | 目标、验收条件、进度、阻塞和下一步 | Forgejo Issue 原文及评论 |
| 实验产物 | 方法、数据和配置版本、结果、失败尝试、局限、后续动作 | 配置、脚本、结果文件和日志 |
| 文件、commit、日志 | 通常不为每个对象重复写一篇自然语言摘要；作为可定位、可校验的证据被摘要引用 | Git 对象或原始文件 |

摘要是派生的研究状态，不覆盖 Issue 原文或实验原始文件。来源引用绑定版本或摘要值；系统能检查来源是否变化，但来源哈希只能证明字节身份，不能证明摘要语义正确。

## Agent 如何使用

Agent 保留 Multiverse 中已有的原始任务指令。启动时系统只提供工具说明，不预选 Issue、不读取摘要，也不组装启动包。Agent 按现有工作流程查看自己可接手的任务，选定 Issue 后，再决定是否调用 Context 工具。

Agent 可先发现相关摘要，再展开证据；也可直接读取已知对象的摘要、证据或原始内容。L0–L3 是不同粒度的视图，不是必须逐级走完的强制流程。返回受 UTF-8 字节预算限制；超出预算时通过 cursor 继续读取，并绑定到读取快照。变化检查按页返回更新，避免一次塞入整个共享仓库。

执行任务的 Agent 撰写自然语言摘要。程序负责检查结构、Issue 和来源绑定、版本与预期修订号，并处理冲突发布；不额外启动摘要模型。摘要可以在阶段性结果或交接时发布，后续 Agent 在同一运行期间主动检查更新并读取。

## 集成边界

Multiverse 监督器托管工具调用，检查 Agent 的仓库范围、版本、读取预算和发布路径。八个工具涵盖任务选择、上下文发现与展开、变化检查、原始证据读取和摘要发布。共享记录存于独立 Forgejo 仓库，任务代码和原始实验产物仍在各自任务仓库。

现阶段集成针对 Multiverse 原生 OpenCode harness。数据仍依赖一个共享 Forgejo 发布点；这不是已经验证的去中心化存储，也没有第二个 MAS 的互操作验收。

## 尚未证实的部分

- 短程受控比较没有发现 Context 优于普通文件或 Markdown 摘要。
- 多轮、长时间研究交接是否能减少过期结论误用、重复实验或上下文成本，尚未验证。
- 自动摘要语义忠实度、跨 harness/MAS 适配和大规模 Agent 并发都仍需单独评估。
- 本设计没有恢复自动启动注入；是否使用上下文由 Agent 根据任务和可用工具决定。
