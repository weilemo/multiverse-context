# CTXVAL-2：下一轮验证方案

状态（2026-11-02）：方案已写成，离线评分、权限和计量校准尚未完成；第二轮模型试验尚未启动。样本、指令和最终评分清单仍须在校准后冻结。本方案不是实验结果。

上一轮把科学计算、历史证据判断、报告发布和跨 Agent 接手合成一个严格完成分数。下一轮将分别报告 Q（科学结果）、E（证据判断）、D（交付）和 H（交接），先定位短程失败来源，再直接检查多轮交接。

## 阶段零：离线校准

不用模型，先验证评测器能区分正确/错误结果、过期或遗漏的摘要、结果正确但交付缺失、证据泄漏、无关文件变化和中断恢复。权限探针要覆盖 Issue 评论、Git、Context 搜索、原始文件、API 和共享卷。计数器要能区分真正跳过已完成计算与重算后得到相同输出。只有参考解、负例、隔离和记录格式通过后，才冻结任务清单。

## 阶段一：证据检索诊断

准备 8 个检查点，比较四种条件，各做两次，共 64 个试次：

| 条件 | 读取界面 | 说明 |
|---|---|---|
| B0 | 普通 Markdown 目录和搜索 | 基础材料说明 |
| B1 | 与 B0 相同 | 增加证据判断清单 |
| C0 | Context 按需工具 | 基础材料说明及必要 API 用法 |
| C1 | 与 C0 相同 | 与 B1 相同的证据判断清单 |

主指标是关键事实是否正确且引用了有效证据；同时记录首个决定性证据的调用数和时间、无关读取、工具错误与用量。四组用于拆开“Context 界面”和“说明更清楚”的作用。它是开发诊断集，不作为全新留出基准上的效果结论。

## 阶段二：短链交接

用新回归、分类和检索任务比较 Markdown 与 Context。每条链为 A 执行并发布、B 独立复核、A 采纳或拒绝，共 12 条链、最多 36 个阶段。盲复核阶段会在权限层阻断 Issue 评论、Git 和 Context 等同伴结果通道；只有提交复核脚本、结果哈希和日志后才解锁比较。

## 阶段三：多阶段研究接力

用三个不同研究项目，每个项目有短/长历史（拟为 10/100 条可回放记录），比较原始文件协作、普通 Markdown 摘要和 Context。每个组合两次，共 36 条五阶段链。阶段包括初始实验、变化后接手、中断恢复、独立复核和综合报告。会计入摘要生成和维护成本，并通过计算计数器判断是否真正复用旧结果。

这些是小规模试点，不足以支持普遍因果结论。主要问题是：长历史和多次交接时，Context 是否能在保持科学结果质量的同时，减少旧结论误用和重复劳动？如果结果只在某类变化场景有用，就限定报告适用范围；若不如普通文件，也保留这一结论。
